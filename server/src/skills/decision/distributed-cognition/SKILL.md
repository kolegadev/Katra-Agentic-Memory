# Distributed Cognition

## Purpose

Use the topology of multiple minds to improve search, verification, and execution without creating correlated consensus or duplicated work.

## Allocation choices

- One persistent agent for continuity-rich, path-dependent work.
- Several blind persistent agents for high-impact hypothesis generation.
- Ephemeral workers for bounded research, extraction, testing, or implementation.
- A challenger separate from the originator for consequential review.
- A synthesizer after independent submissions are committed.

## Procedure

1. Classify the work mode and independence requirement.
2. Determine whether identity history is useful or contaminating.
3. Rank candidates using domain experience, cognitive disposition, relevant memories, prior outcomes, epistemic diversity, workload, capability fit, and conflict penalties.
4. Exclude the custodian from normal mission work.
5. Assign one accountable owner per work item.
6. Issue recipient-specific batons and leases.
7. Prevent blind workers from seeing incumbent conclusions or each other's drafts.
8. Require provenance and a typed delta from each result.
9. Synthesize only after independent outputs are durable.
10. Cancel duplicate, stale, or low-value work and record why.

## Persistent versus ephemeral

Prefer a persistent identity when autobiographical continuity, long-running judgment, or an evolved perspective is part of the computation. Prefer an ephemeral worker when the task is narrow, independently verifiable, and should not alter identity or require private memory.

## Consensus rules

Agreement is not evidence when contexts, sources, or prompts are correlated. Preserve minority hypotheses with credible evidence. Escalate unresolved high-impact conflicts rather than forcing a single narrative.

## Completion

Every active work item has one owner, a current lease, a clear deliverable, a baton version, and a defined merge path.
