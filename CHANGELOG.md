## [Unreleased]

> ⚠️ **Deployment precondition — ship this server change and the bridge update together.**
> `GET /api/v1/admin/personality` is **caller-pinned and authenticated**: it resolves the
> caller's own identity record and requires a key (it left the no-auth allowlists), and
> `?user_id=<another identity>` requires the admin key. From this iteration the Kolega Code
> bridge does exactly that — `kolega_katra_bridge/config.py` (`_fetch_server_personality`) sends
> `Authorization: Bearer <api_key>` with `?user_id=<its identity>`, caches per identity, and
> reports a rejected key once per cache window ("personality sync rejected the bridge key;
> continuing with the local personality") instead of failing open in silence. A bridge still
> running the pre-iteration fetch (a plain `client.get(url)`, no `Authorization` header) is
> rejected by this server and **fails open**, so the dashboard silently stops governing its
> retrieval. Deploy the bridge with — or before — the server change.

### Added
- **Creative Baton, plateau cycles, controller adapter and resume (ITER-7, `FOCUSED_IMAGINATION` + `CREATIVE_BATON_PROMOTION`, both default off)** — Phase 5 closes the loop: a **stalled** mission runs **exactly one** imagination cycle, receives a **sanitised, versioned Creative Baton**, has its candidates turned into controller work items, records what happened, and resumes correctly after a restart. New `server/src/services/processing/imagination-cycle-service.ts` (plateau evaluation + the cycle orchestrator), `creative-baton-compiler.ts`, `creative-baton-promotion.ts`, `imagination-outcome-service.ts` (adapter + outcome feedback), `creative-baton-collections.ts`, `imagination-cycle-config.ts` and `creative-baton-tools.ts`, plus `creative-baton.schema.json` registered in the mission-cognition registry. **The gates, in the contract's fixed order:** single-flight (a concurrent caller joins the running cycle instead of starting a second one) → the **persisted** cooldown → the per-mission **window budget** (cycles *and* measured tokens from the usage ledger) → the **plateau evaluation**. `force: true` bypasses the plateau gate only — never the cooldown or the budget — and a **skipped cycle writes nothing at all**: no cycle row, no state change, no baton, no model call. **Nothing about the cooldown, the budget or the claim lives in memory:** `imagination_cycle_states` holds one row per `{user_id, mission_id}` (cooldown deadline, window counters, last cycle/baton/stop reason, the no-new-cells streak, the novelty means), and `imagination_cycles` holds one row per claimed cycle, unique per **`{user_id, mission_id, cycle_id}`** with a **derived** `cycle_id` (`imagination_cycle_<scope16hex>_v<version>_c<ordinal>`, where the scope digest covers the identity AND the mission), so two concurrent callers of ONE mission compute the same id and exactly one insert wins, while two DIFFERENT missions that share (version, ordinal) derive different ids and each run their own cycle — the claim lookup is scoped to the same key, so no mission can read, replay or inherit another's trace, baton or counts. A completed row replays and an abandoned one is stepped over rather than wedged. The plateau is the brief's §4.1: **below-minimum active candidates** (`IMAGINATION_PLATEAU_MIN_CANDIDATES`, 3), **novelty gain below ε over N rounds** (`…_NOVELTY_EPSILON` 0.05 / `…_NOVELTY_ROUNDS` 2, derived from the persisted means), a **repeated failure signature**, **archive coverage below a floor** (6 cells) and **contradiction pressure above a threshold** (2 live contradictions) — each reported with the evidence that decided it, so "not a plateau" comes with five numbers rather than silence. Every cycle records the counts, the effective budget and what was actually spent, the coverage view **with its scan bounds and a `truncated` flag**, and which **stop condition** fired (budget exhausted · coverage target reached · no candidate above the novelty/coherence floor · two consecutive rounds without a new cell · a high-value candidate promoted and the inventory restored · privacy validation failed · mission cancelled/superseded · completed), with all of them reported and the first met one in precedence order winning
- **The Creative Baton is an allow-list, and promotion is explicit and idempotent** — `compileCreativeBaton` builds the brief's §4.3 packet **field by field**: the portfolio carries the candidate's own hypothesis, mechanism, descriptor bins, scores, cheapest test, lineage ref and `privacy_safe: true` (and nothing else), `attention_targets` is DERIVED from each signal's kind and calibration numbers (never its statement or its own `why_operationally_relevant`), and `excluded_regions[].pattern` is a FINGERPRINT (`region_N:<kind>:sha256:<16 hex>` — never the ruled-out text). Evidence refs, changed premises, bridge paths, parent links and cell keys have no place in the shape at all. Every compiled baton is validated against `creative-baton.schema.json` and **secret-scanned with the same patterns the mission's own batons use** (`assertNoSecretMaterial`) before it is written, and carries a `payload_hash` over the canonical sanitised payload. `promoteCreativeBaton` is the ONLY code that writes a shared scope: it requires **both** flags and a **trusted** caller, **re-validates the stored document** (schema, secret scan, `creative_baton_version`, and the payload hash recomputed against the one the compiler wrote), refuses a tampered baton with a **named reason** (`payload_hash_mismatch`, `schema_invalid`, `secret_material`, …) instead of sharing it, writes the promotion audit row (`creative_baton_promotions`: promoting identity, timestamp, schema version, payload hash) and is **idempotent** — promoting the same payload twice reports the existing promotion and writes nothing
- **Controller adapter + outcome feedback** — `batonCandidatesToWorkItems` turns a baton's eligible candidates into work items **through the existing funnel**: `work-item-generator.ts` gained an `extra` input and `SchedulerService.upsertWorkItems(missionId, { extra })` forwards it, so there is no new write path into `cognitive_work_items`, the items get the mission's own priority feature vector, the funnel's `{mission_id, trigger, description}` dedupe makes the adapter idempotent, and each item carries `[creative_baton <id> seed <id>]` in its description plus a `provenance` row field (`{source, baton_id, seed_id, cycle_id, requested_by}`). The trigger **reuses the existing `manual` value** (no enum member had to be invented: the item exists because a caller explicitly asked for it) with mode `explore`; an untrusted caller may only adapt a **promoted** baton, because the work queue is shared state. `recordCandidateOutcome` (`useful_information` / `mere_variance` / `unnecessary_cost`) feeds the archive's identity-bound `recordOutcome`, the existing `trigger-telemetry` instrument (measured token cost, grouped under the new `imagination_candidate` trigger type; the telemetry note carries ids only, never the caller's `detail`) and a **capped** novelty-drive replenishment (`+0.05` per useful outcome, at most `0.2` per identity and mission per rolling 24 h, computed from the **stored** outcome rows so a restart cannot refill the same budget). Idempotent per `{seed, outcome}`: a repeat is recorded once and reported as a repeat; a different outcome for the same seed is a new record
- **Five new MCP tools** (`FOCUSED_IMAGINATION=1`, plus `promote_creative_baton` behind `CREATIVE_BATON_PROMOTION=1` too) — `run_imagination_cycle` (run, or `mode: "evaluate_only"` / `dry_run` to see the plateau conditions, the persisted state, the window budget and the cooldown with **zero writes**), `get_creative_baton` (caller/scope-aware: own batons plus promoted ones), `promote_creative_baton` (trusted callers only), `baton_candidates_to_work_items` and `record_candidate_outcome`. Documented in `docs/MCP-TOOLS.md` (catalogue, the flag table: +8 → **89**, and **90** with `CREATIVE_BATON_PROMOTION=1`; the promotion flag on its own adds nothing) and `.env.example` (both flags + the cycle budget/cooldown knobs). With either flag off the tools are `Unknown tool`, nothing is written and no model call is made
- **`imagination_cycle_states`, `imagination_cycles` and `idea_candidate_outcomes` are personal kinds** — added to `PERSONAL_KINDS`, written through `resolveWriteScope`/`stripSharedId`, so the cooldown/budget state, the cycle ledger and the outcome rows can never carry a shared scope. `creative_batons` is deliberately NOT a personal kind (the compiled baton is the one shareable artifact, written privately at compile time and promoted by the gated promoter) and `creative_baton_promotions` is the team-scoped audit of that promotion. Indexes are owned by the feature (`ensureCreativeBatonIndexes`, the lazy house guard memoised per store) and deliberately NOT declared in `MEMORY_SYSTEM_INDEXES`
- **ITER-6 residuals fixed** — (F1) **one effective threshold**: `CONTAINMENT_THRESHOLD` now IS `PARAPHRASE_THRESHOLD` (0.72), so the containment branch fires exactly at the gate the archive compares against and the 0.7-vs-0.72 dead band is gone; (F2) the **seed path compares like the exclusion path** — hypothesis against hypothesis, mechanism against mechanism and concatenation against concatenation, taking the maximum — so a verbatim hypothesis with a freshly worded mechanism can no longer dilute the overlap and be admitted as new; (F3) the **finite vacuity stoplist and the absence of synonym rewriting are documented in the module header** (behaviour unchanged). Coverage now reports its **scan bounds** (`cells_limit`/`cells_scanned`/`cells_truncated`, `seeds_dedupe_limit`/`seeds_scanned`/`seeds_truncated`) and a single `truncated` flag, in the coverage view **and** in the baton, so a bounded scan is never presented as the whole archive
- **Imagination engine + quality-diversity idea archive (ITER-6, `FOCUSED_IMAGINATION`, default off)** — Phase 4 turns a Salience Trace into a **diverse, reproducible portfolio of testable hypothesis seeds**. The brief's **ten operator families** (`assumption_inversion`, `representation_shift`, `distant_analogy`, `constraint_mutation`, `boundary_extreme`, `causal_reversal`, `contradiction_preservation`, `tool_invention`, `random_semantic_bridge`, `counterfactual_world`) are selected **from the trace itself** — tensions and persistent pulls drive constraint mutation and contradiction preservation, absences invert assumptions, surprises reverse causes, attractions shift representation, questions bridge distant associations — with intensity setting the score order and a **seeded** tie-break deciding the rest, so the run's `operator_plan` records which operators ran, on which signal ids, and why (an operator that cannot run, e.g. no bridge path, is recorded as *skipped*, never run as a fabrication). New `server/src/services/processing/imagination-service.ts` (+ `imagination-operators.ts`, `imagination-collections.ts`, `imagination-tools.ts`) and `idea-archive-service.ts`. **Determinism is structural, not hoped for:** every random choice comes from a seeded PRNG (mulberry32 over a hash of the run's seed) and every id is **derived** (`sha256` over the seed's content + the seed + the mission) — never a random UUID — so two runs with the same seed over the same inputs produce a byte-identical portfolio (`portfolio_digest`, computed over the payload with timing/bookkeeping fields stripped, proved across an advanced clock by test), and a different seed yields a different, still schema-valid portfolio. Every seed must cite the trace signal ids or the mission's ledger/delta/work-item/baton ids: an unresolvable ref is **dropped and counted**, never stored and never replaced by an invented one, and a seed left with no evidence is dropped with a counted reason; **novelty is measured against the archive** (`min(model claim, 1 − max similarity)`), not taken on faith
- **The distant-association walk returns the path** — a bounded (2–3 hops, ≤3 paths, ≤400 nodes / ≤1200 edges), **seeded**, **cycle-safe** multi-hop walk over the caller's own `knowledge_nodes`/`knowledge_relationships` with a low-degree preference, so `random_semantic_bridge` and `distant_analogy` must **state the bridge** the walk found (a bridge seed without a path or without a stated bridge is dropped and counted). Deviation from the brief, recorded: the walk uses this repo's real edge collection (`knowledge_relationships`), not the `knowledge_edges` name the contract assumed
- **Quality-diversity archive** (`idea_archive_cells`, one cell per descriptor-bin tuple) — five descriptor dimensions (`mechanism`, `representation`, `violated_assumption`, `evidence_family`, `test_strategy`), a documented quality function (`quality = f(novelty, coherence, testability, information_gain)`, fixed weights summing to 1), and one **incumbent per cell** (the highest-quality seed; a challenger that does not beat it is admitted below the incumbent and the cell's history says so). **Deterministic dedupe with recorded reasons:** exact duplicates are `duplicate_of`, near-duplicates `paraphrase_of` and matches against the mission's exclusion list (rejected ledger hypotheses + the trace's own low-confidence regions) are `excluded_region`, decided by **content-token containment** (`|A ∩ B| / min(|A|, |B|)` over stopword-filtered tokens, at least two shared tokens, at `CONTAINMENT_THRESHOLD` — which since ITER-7 **is** `PARAPHRASE_THRESHOLD`, see the residuals entry above; it was 0.7 while the gate was 0.72, the dead band that entry closes) *as well as* by Jaccard over the normalised token sets (`PARAPHRASE_THRESHOLD = 0.72`, with the length guard `LENGTH_GUARD_RATIO = 0.5` applied only where containment is genuinely low) — so a stored statement padded with hundreds of extra characters is still a restatement rather than a new idea. Rejections are **stored with their reason**, which is what makes an exclusion durable — and what a **changed-premise re-entry** must cite: a ruled-out idea comes back only with a **valid** premise (a complete sentence that is *not* a no-change assertion — `nothing has changed`, `no change`, `unchanged`, `as before`, … — and that introduces at least two content tokens the excluded text does not already contain) **and** a lineage link to the prior rejection, and the cell's history records the re-entry. Coverage is the sanitized surface (`cells_total`, `cells_by_dimension`, `new_cells_this_cycle`, `occupancy`, `gaps` and incumbent ids/bins/quality) and carries **no seed statement, mechanism or evidence text**
- **`generate_imagination_seeds` + `get_idea_archive` MCP tools** (`FOCUSED_IMAGINATION=1`, default off) — the run tool is a **write** an untrusted caller may only use on a mission it owns and it **does not promote anything** (no promotion path exists before Phase 5); the read tool is caller-pinned and returns the sanitized coverage view plus incumbent summaries (cell key, bins, quality, seed ids). Documented in `docs/MCP-TOOLS.md` (catalogue + the flag table: +4 → **85**, 86 with the personality flag, 110 with the cognitive-control row, 123 with a scheduler mode, 124 with all of them on), the README and `.env.example`
- **`idea_seeds` + `idea_lineages` are personal kinds; `idea_archive_cells` is identity-owned** — the seeds and their lineage rows go through `resolveWriteScope`/`stripSharedId` like every other personal kind, and the archive cells (unique `{user_id, mission_id, cell_key}`) are written with the policy's explicit private opt-out, so **no document in any of the four collections can carry a `shared_id`**. Indexes are owned by the feature (`ensureImaginationIndexes`, the lazy house guard memoised per store) and deliberately NOT declared in `MEMORY_SYSTEM_INDEXES`, so a flag-off deployment never creates the collections. The seed has its own draft-2020-12 schema (`idea-seed.schema.json`), registered next to the salience trace in the mission-cognition registry and **validated before every store**
- **Budgets, recorded as planned vs actual** — hard caps on seeds (`FOCUSED_IMAGINATION_MAX_SEEDS`, default 8), operators (`FOCUSED_IMAGINATION_MAX_OPERATORS`, default 6) and model calls (`FOCUSED_IMAGINATION_MAX_LLM_CALLS`, default 3 — two operators share one bounded `extractJson` call under the mission's usage origin), plus a token ceiling and a hard timeout. A caller may ask for **less** than the deployment allows and can never ask for more: every requested cap is `min(requested, environment)`, the operators the call budget cannot afford are recorded as skipped (`llm_call_budget`) rather than silently dropped, and `imagination_runs` carries the effective budget, the plan, the per-reason drop counts and the planned-versus-actual counts. One run per `{user, mission, cycle, seed}` — a repeat replays the recorded run with no model call and no new documents
- **Focused consolidation + the private Salience Trace (ITER-5, `FOCUSED_IMAGINATION`, default off)** — a mission-scoped analogue of sleep consolidation: given a mission's **real operational state** (mission state at its current version, the active Context Baton, the epistemic ledger's hypotheses/uncertainties/decisions, open uncertainties via the existing deterministic detectors, the work-item queue, accepted state deltas since the last checkpoint, and the identity's own reflection state as **counts only**) it privately produces an **evidence-linked, calibrated Salience Trace** — attractions, tensions, surprises, absences, persistent pulls and questions, each with `why_operationally_relevant` and evidence refs — plus its own run ledger. New `server/src/services/processing/focused-consolidation-service.ts` with a deterministic `problem_state_digest` (ids, versions, statuses, counts and statement prefixes only — no timestamps, no generated ids, no model output), one bounded `llmService.extractJson` call per run (at most one retry, `FOCUSED_CONSOLIDATION_MAX_TOKENS` ceiling, `FOCUSED_CONSOLIDATION_TIMEOUT_MS` hard timeout) attributed through `runWithUsageOrigin({ mission_id })`, idempotency per `{mission_id, cycle_id}` (in-process single-flight **and** a unique `idempotency_key`, so a concurrent duplicate runs exactly once and a repeat replays the recorded trace without calling the model), and fail-loudly semantics: a failed or unusable model output writes a `failed` run row with the error and **no trace**. Evidence is never invented — every `evidence_refs` entry must resolve against `mission_states` / `state_deltas` / `epistemic_entries` / `cognitive_work_items` / `cognitive_batons` for that mission, unresolvable refs are kept, flagged (`unresolved_evidence`) and counted on the trace and the run, and more than half the signals carrying unresolved evidence records a **warning** instead of passing silently. Calibration is bounded and hostile-output safe: `intensity`/`confidence` clamp to 0..1 and `valence` to −1..1, non-finite or missing values fall back to 0 with every adjustment counted (`clamped_values`, per field), signals below the 0.2 confidence floor are kept and marked `low_confidence`, unusable signals are dropped with counted reasons, and extra keys the model invents are dropped rather than stored
- **`salience_traces` + `focused_consolidation_runs` are personal kinds** — added to `PERSONAL_KINDS`, written through `resolveWriteScope` (which returns `shared_id: null` for a personal kind however the caller asks) and `stripSharedId`, so no document in either collection can carry a shared scope and no shared/team read path exists for them. Indexes are owned by the feature (`ensureFocusedConsolidationIndexes`, the lazy house guard, memoised per store, like the mission-cognition collections and deliberately NOT declared in `MEMORY_SYSTEM_INDEXES` so a flag-off deployment never even creates the collections): unique `trace_id`, read `{user_id, mission_id, created_at: -1}`, unique `idempotency_key`, read `{user_id, mission_id, cycle_id}`
- **`run_focused_consolidation` + `get_salience_trace` MCP tools** (`FOCUSED_IMAGINATION=1`, default off — with the flag off they are absent from `tools/list` and the dispatch throws the plain `Unknown tool`, writing nothing and calling no model) — the run tool is a **write** an untrusted caller may only use on a mission it owns, and the read tool is **caller-pinned**: an untrusted caller only ever reads traces written under its own identity, never another identity's, even when it names that identity's `user_id`. Documented in `docs/MCP-TOOLS.md` (catalogue + the flag table: +2 → **83**, 84 with the personality flag, 108 with the cognitive-control row, 121 with a scheduler mode, 122 with all of them on), the README, `.env.example` and `CHANGELOG.md`
- **Durable, identity-scoped self-model (ITER-4)** — the cognitive identity stops leaking and stops evaporating. `agent_beliefs` rows carry a `user_id` on every write and every read (`trackBelief(userId, …)` / `getAgentBeliefs(userId, …)`, `user_id` part of the upsert filter, no hardcoded `default` any more) and are guarded by a unique `{user_id, entity_name, proposition}` index; because older deployments hold duplicate keys under the legacy identity-less value, that index is built by an **idempotent, logged migration** (`dedupeAgentBeliefs()`, run by `runDatabaseMigrations()` *before* index initialisation) which counts the duplicates, collapses each key group deterministically (highest `confidence`, then newest `last_updated`, then lowest `_id`), logs *and returns* the documents removed and groups touched, and only then creates the index — a second run reports zeros and writes nothing, and lone legacy rows are left exactly as they are. ### Changed
- **Promotion is a trusted-caller operation (recorded reading of the brief, ITER-7)** — the contract's security section says untrusted callers cannot promote, and promotion is the one operation in this feature that writes TEAM state. So `promote_creative_baton` (and the cycle's own promotion step) requires a trusted caller: an untrusted caller is refused with `untrusted_caller` and nothing is written, while the cycle still compiles and stores its baton privately and records the skip (`promotion_skipped: 'flag_off' | 'untrusted_caller'`). The adapter follows the same rule from the other side: an untrusted caller may only turn an ALREADY-PROMOTED baton into work items, because the work queue is shared state. The reasoning is recorded in `creative-baton-promotion.ts`, `imagination-outcome-service.ts` and here
- **The cycle is PULL, never a cron (recorded, ITER-7)** — there is no interval, no timer and no background loop: `runImaginationCycle` is called by the MCP tool (or by whatever tick the executive already runs), and everything that makes it safe under concurrent callers and across restarts lives in the store (the cooldown/budget state row, the derived unique `cycle_id`, the in-process single-flight slot as a fast path only). A restart therefore re-reads the same facts and cannot re-trigger early — proved by a restart test that swaps in a fresh module graph over the same store
- **The ITER-6 archive is privacy-first, not shareable (recorded reading of the brief)** — the brief calls the quality-diversity archive "mission-scoped". It is realised **identity-owned** instead (`idea_archive_cells` keyed `{user_id, mission_id, cell_key}`), because a cell's meaning is a *private seed id* (`incumbent_seed_id`): sharing cells would leak the shape of an identity's portfolio while staying undecodable to anyone who cannot read the seeds. The shareable surface is the sanitized coverage view. The reading is recorded in the module headers (`imagination-collections.ts`, `imagination-service.ts`) and here
- **Focused consolidation does NOT refactor the sleep path (deliberate deviation, ITER-5)** — the brief suggested extracting shared primitives out of `sleep-consolidation-service.ts`. Rejected: that service's gather is entangled with period semantics (period_start/period_end, batched synthesis, the journal output bus) while the focused inputs are mission-scoped, so the two share no gather and a "shared primitive" would only couple them. The iteration instead reuses `llmService.extractJson`, the mission-cognition services (mission state / state deltas / epistemic ledger / batons / uncertainty triggers) and the mission-cognition schema registry — where `salience-trace.schema.json` is registered next to the six control-plane contracts, so there is one Ajv2020 instance rather than a second validator. `sleep-consolidation-service.ts` and every journal/reflection writer are untouched, and a source-level guard (`server/tests/unit/focused-consolidation.test.ts`) proves the new module imports none of them and writes to no journal-family collection
- **Personality endpoints are caller-pinned and authenticated** — `GET`/`PUT /api/v1/admin/personality` left the no-auth allowlists (`middleware/caller-auth.ts`, `admin-routes.ts`): the record now resolves for the resolved caller, `?user_id=<id>` (another identity) requires the admin key, and the dashboard sends `Authorization`. `GET /api/v1/admin/personality/profiles` stays public — it is a static catalogue. Resolution never writes or migrates, so no identity inherits another's configuration and the legacy record is untouched
- **Naming your OWN identity is not naming another one** — `GET`/`PUT /api/v1/admin/personality?user_id=<the caller's own id>` now behaves exactly like omitting the parameter (200, resolved and pinned to the caller), so a client can always state who it is; the comparison is made against the resolved caller, so any other id stays admin-gated (401 without the admin key). This is what lets the Kolega Code bridge send its identity unconditionally

### Fixed
- **The ITER-7 cycle claim was not mission-scoped, promotion re-validation was integrity-only, and three counters lied (ITER-7 refinements, found by an independent verifier)** — six corrections, each pinned by a test written to fail against the previous code. **(1) The blocker:** `cycleIdFor(missionVersion, ordinal)` derived `imagination_cycle_v<version>_c<ordinal>` with no mission or identity component, `imagination_cycles` was unique on `cycle_id` alone and `claimCycle` looked the row up by `cycle_id` alone — so two missions sharing a (version, ordinal) shared a cycle. Reproduced across identities: the second mission's cycle never ran and its caller received the first mission's `trace_id`, `baton_id`, portfolio counts and digest (`status: "replayed"`, `reason: "recorded_cycle"`, `rows_for_b_mission: 0`). The id now carries a scope digest (`imagination_cycle_<scope16hex>_v<version>_c<ordinal>`) derived from the identity AND the mission, the claim/lookup/update filters are `{user_id, mission_id, cycle_id}`, and the unique index (and the suite's `UNIQUE_INDEXES`) is the same compound key, so two missions each run their own cycle and never see each other's ids. **(2)** `creative-baton.schema.json` had `additionalProperties: true` everywhere and `payload_hash` is an unsigned sha256 over the stored document, so a store-level writer who recomputed the hash could promote a packet carrying an extra key inside a candidate; every object in the schema is now `additionalProperties: false`, so an extra key fails at compile, promote AND read — including when the hash is recomputed — while the hash check stays. **(3)** A post-promotion tamper was never re-detected: reads served the tampered row, the adapter copied its text into the SHARED queue, and a second promotion short-circuited on the existing `shared_id`. Every read FOR USE now verifies the stored baton first (`verifyStoredBaton`: format version → closed schema → secret scan → recomputed payload hash) and refuses it BY NAME (`payload_hash_mismatch`, `schema_invalid`, `secret_material`, `version_unsupported`) — the read tool, `compileAndStore`'s reuse path, the adapter and the promotion idempotency path, where the re-validation now runs BEFORE the no-op answer. **(4)** `coverage_gaps[].unoccupied_bins` was copied verbatim from the coverage view, so an injected marker reached the baton; the compiler now re-validates every bin against the archive's closed `DESCRIPTOR_BINS` vocabulary (and every dimension against `DESCRIPTOR_DIMENSIONS`), dropping and counting what is unknown. **(5)** `runImaginationCycle` returned `status: 'ran'` for cycles whose stored row was `failed` (upstream failure, privacy validation, a cancelled mission) with no baton; the status now agrees with the row (`failed` with the same `reason`/`stop_reason`), so a caller reading only `status` is not misled. **(6)** The adapter's `created` counter reported only baton-derived items while the funnel also inserts its own derived work (measured 3 rows added vs `created: 2`), so the result now reports `work_items_added_total` — measured from the store before and after the call — alongside `created`/`reused` and `funnel_derived_added`. `tests/unit/imagination-cycle.test.ts` (33 tests) and `tests/unit/creative-baton.test.ts` (31) carry the new constructions, and `tests/security/creative-baton-privacy.test.ts` adds the tampered-shared-baton case
- **The ITER-6 dedupe gate could be defeated by padding, and the changed-premise gate was shape-only (ITER-6 refinements, found by an independent verifier)** — `statementSimilarity` was Jaccard behind `LENGTH_GUARD_RATIO = 0.5`, which returned **0** whenever one statement was more than twice the other's length: a stored seed's statement with ~840 characters of filler appended (or any verbose restatement) was **admitted** as a new idea, and because the stored novelty is `min(model claim, 1 − max similarity)` it also kept its self-reported novelty — defeating both the paraphrase gate and the archive-measured novelty rule. Similarity is now decided by **content-token containment** first (`|A ∩ B| / min(|A|, |B|)` over stopword-filtered tokens, ≥ `CONTAINMENT_THRESHOLD = 0.7` with at least `MIN_CONTAINMENT_OVERLAP = 2` shared tokens), with the length guard demoted to the Jaccard branch, which is consulted **only where containment is genuinely low** — a padded restatement now measures 1.0 containment (and 0 novelty) instead of 0 similarity, while a genuinely different long text is still admitted. Three more holes closed at the same time: **two candidates with identical content in one cycle** derive the same `seed_id`, and the second was counted as "below incumbent" with `seeds_rejected = 0` and an empty rejections list — it is now reported as an explicit `duplicate_of` rejection naming the stored seed; **`recordOutcome` matched by seed id alone when the identity was omitted or empty**, so it could append to another identity's lineage — the identity is now required and is part of the lookup, and an empty one is a caller error; and the **changed-premise gate** accepted "Nothing has changed here at all." because it checked shape only (≥5 words and a terminator) — a valid premise must now also pass a documented no-change stoplist (`nothing has changed`, `no change`, `unchanged`, `as before`, …) and introduce at least `MIN_CHANGED_PREMISE_TOKENS = 2` distinct content tokens (≥4 characters, stopword-filtered) that the excluded/rejected text does not already contain, with the two new reasons (`vacuous_changed_premise`, `premise_restates_exclusion`) added to the seed schema's rejection enum. `tests/unit/imagination-engine.test.ts` pins each hole with the construction that used to pass
- **The goal-directed mind-wander found no edges on any real knowledge graph (pre-existing defect, fixed in ITER-6)** — `SelfModelService.generateGoalDirectedMindWander` filtered edges with `{ $or: [{ source: node._id }, { target: node._id }] }`, but stored edges carry `from_id`/`to_id` (and `source` is a *provenance label* on code-graph edges — the literal string `'katra-code'`), so the query matched nothing, every wander ended after exactly one node, and the "goal-directed" walk was indistinguishable from the no-op it had become. The walk now reads the real schema through one tolerant reader (`from_id`/`to_id`, tolerating `source`/`target`), resolves endpoints against the node's graph `id` as well as its `_id`, and looks the next node up by `id`, then `_id` (then a real `ObjectId`, for legacy rows); the non-goal `generateMindWander` uses the same reader so both walks agree on what an edge is. Four bounded `$in` queries per step replace the `$or`, which also makes the traversal testable against the unit suite's Mongo fake. `server/tests/unit/imagination-engine.test.ts` seeds a real `from_id`/`to_id` chain and asserts the path actually traverses it (and that a `source`/`target` chain does too)
- **Focused consolidation: one character over a schema bound failed the whole run, and a failed run could leave a complete trace behind (ITER-5 refinements)** — `truncate()` returned `max` characters *plus* the ellipsis, so a 2001-character `statement`/`why_operationally_relevant` was stored as 2001 characters against `maxLength: 2000`, the store rejected the whole document and the run failed with **no trace written at all** (measured: 2000 characters completed, 2001 failed, 1 MB failed the same way). Truncation now fits the bound *including* the ellipsis, and every shortened field is counted as `truncated_fields` on the run ledger instead of being degraded silently. In the trace/ledger window — an insert and the update that names it, which cannot be one transaction here — a failed ledger write now **compensates**: the trace is deleted (bounded retry) so a failed run leaves no readable trace, and if that delete also fails the run row names the surviving trace in `orphan_trace_id` and the mismatch is logged loudly, instead of a `failed` run with `trace_id: null` sitting next to a complete valid trace. A `running` claim whose `created_at` is missing or unparseable could never satisfy the staleness test, pinning `{user, mission, cycle}` at `in_progress` forever (unstuck only by inventing a new cycleId); an un-ageable claim is now reclaimed as failed, while an ageable one still waits for the timeout + grace window. - **Beliefs leaked between identities and evaporated on restart** — `trackBelief` hardcoded `user_id: 'default'` on insert while `getAgentBeliefs` filtered by `entity_name` alone, so every identity read (and overwrote) the same rows, and the whole procedural map died with the process. Beliefs are now written and read per identity (a write without an identity is refused, never attributed to anyone) and procedural patterns are persisted per identity, so an untrusted caller can no longer read or write another identity's beliefs or habits, and a restart no longer forgets them. `server/tests/unit/self-model-identity.test.ts` proves both, including the restart and the migration's second-run no-op; `tests/security/user-id-scoping.test.ts` covers the beliefs/procedures cases
- **Concurrent personality writes lost a version increment** — the flag-on `PUT` read the record and then wrote `version + 1` unconditionally, so two simultaneous updates both reported the same version and the second silently overwrote the first. The write is now a bounded compare-and-set on the observed version (`updateOne({key, version: observed})`, re-read and retry on a miss), so interleaved updates land as sequential increments with the last writer's payload; exhausted retries return **409** rather than a version that was never stored
- **Two identities creating their first personality record at once silently discarded a payload** — the create branch upserted on the key alone, so a record another writer created between our read and our write was matched and overwritten with `version: 1`, losing that writer's payload and its increments. The create is now guarded with `{ key, version: { $exists: false } }` and a create that *matches instead of inserting* (or that the unique `key` index refuses as a duplicate) is retried through the guarded update path: `version` is the number of successful writes, and every landed write moves it by exactly one
- **A hand-written or pre-versioned identity record was permanently unwritable** — the write guard asked for the *absence* of `version` whenever the stored value was not a finite number, which a record that has the field never satisfies: every attempt missed and the write returned **409** forever.
