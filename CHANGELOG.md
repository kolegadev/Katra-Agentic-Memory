## [Unreleased]

> ⚠️ **Deployment precondition — ship this server change and the bridge update together.**
> `GET /api/v1/admin/personality` is **caller-pinned and authenticated**: it resolves the
> caller's own identity record and requires a key (it left the no-auth allowlists), and
> `?user_id=<another identity>` requires the admin key. From this iteration the Kolega Code
> bridge does exactly that — `kolega_katra_bridge/config.py` (`_fetch_server_personality`) sends
> `Authorization: Bearer <api_key>` with `?user_id=<its identity>`, caches per identity, and
> reports a rejected key once per cache window ("personality sync rejected the bridge key;
> continuing with the local personality") instead of failing open in silence. A bridge still
> running the pre-iteration fetch (a plain `client.get(url)`, no `Authorization` header) is
> rejected by this server and **fails open**, so the dashboard silently stops governing its
> retrieval. Deploy the bridge with — or before — the server change.

### Fixed
- **Four observability residuals, closed in ITER-10 — each pinned by a test that fails against the pre-fix sources** (the new cases in `imagination-dashboard.test.ts` and `imagination-metrics.test.ts`; 11 assertions fail before the change). **(1) `/imagination/traces` was the one number-carrying view with no view-level `basis`:** it now carries the same house shape the metrics carry (`window` — `from`/`days` null, because a listing is not a windowed rate, `to` the moment of the read —, `n`, `sources`, `minimum`, `measurement`), asserted at the payload level AND at the source level, with the per-trace calibration and evidence counts unchanged. **(2) The experiment note was bounded only on the MCP surface:** `POST /experiments/observations` accepted a 1,048,595-character `note` because only the zod schema capped it, and the service had no bound at all. The service now enforces `EXPERIMENT_NOTE_MAX_LENGTH` (2000) and refuses **by name** (`note_too_long`) before a row — or an audit row — is touched; the MCP schema caps with that SAME exported constant and a test asserts the two numbers are equal, so the surface and the service cannot drift; a note at the limit still records byte-for-byte. **(3) `cost_of_novelty` read as "free" when the spend was merely unrecorded:** a window with a useful candidate but no cycle recording tokens returned `ok` with `tokens_per_useful_candidate: 0`. It now returns `ok` only when at least one included cycle recorded a non-zero `budget.tokens_spent_this_cycle`, and otherwise `insufficient_data` whose basis and reason state that the spend is **UNRECORDED, not zero**; the zero-denominator case keeps its own, different, stated reason. Both branches are tested, plus a cycle row with no `budget` at all and a window with no cycle. **(4) Trusted-caller scope is explicit and consistent:** `/overview`, `/cycles`, `/cycles/:cycleId`, `/traces` and `/batons` used to query across EVERY identity for a trusted caller with no `user_id`, while the per-identity views pinned to the caller. EVERY view now defaults to **the caller's own identity — trusted or not** — and every payload states its scope (`scope: { kind: 'caller'|'named'|'all', identities: n }`, including the flag-off payloads and the one gated write's response). A trusted caller may name ONE identity (`?user_id=`) or, on the views that can span identities (`/overview`, `/cycles`, `/cycles/:cycleId`, `/traces`, `/batons`), opt in to every identity with `?all_identities=1`; `user_id` wins when both are given, so a read can never widen by accident, and an untrusted caller's parameters are IGNORED, never honoured. The batons view's default is the caller's own batons plus the PROMOTED (shared) artefact, so the one shareable surface still reaches a non-owner and a private row of another identity no longer reaches a trusted caller by default. Documented in the route header, in the new "Read scope" section of `docs/IMAGINATION-ROLLOUT.md`, and rendered by the dashboard's traces view (`dashboard/cognition/index.html` prints the object basis as one sentence instead of `[object Object]`). No metric's meaning, no flag default and no write path changed; every GET is still a read.

### Added
- **Imagination observability — read-only dashboard views, basis-carrying metrics, experiment records and a documented canary policy (ITER-9, Phase 7, no new flag)** — an operator can now see **why a cycle triggered, what it generated, what it rejected and whether value improved versus a baseline** without a single write path into the engine. New `server/src/services/processing/imagination-metrics-service.ts`, `imagination-experiments.ts`, `imagination-observability-tools.ts` and `server/src/routes/imagination-dashboard-routes.ts` (mounted at `/api/v1/imagination`), plus the ITER-9 section of `dashboard/cognition/index.html` and `docs/IMAGINATION-ROLLOUT.md`. Views: `overview`, `cycles`, `cycles/:cycleId` (the plateau conditions with their evidence, every stop condition with whether it was met, the counts, the rejections **with reasons** and the tokens/budget), `traces` (own only — signals as shapes plus calibration and evidence COUNTS, never the statement text), `archive` (coverage with its scan bounds + sanitised incumbents), `batons` (each row re-verified before display, plus the promotion audit), `team` (modes, envelopes, allocation reports), `metrics`, `experiments` + `experiments/compare`, and `rollout`. Every view states why it is empty (family flag off, team flag off, mission-scoped read without a `mission_id`, or simply no data), carries a privacy indicator (`private`/`shared`/`private+shared`, `private_rows`, `shared_rows`, `raw_reflections_included: false`) and names the collections its numbers came from.
- **Metrics that state their basis, and a privacy count that is an audit** — `useful_novelty_rate` (n ≥ 5 recorded outcomes), `archive_coverage_gain`, `idea_survival` (declared as a **proxy**), `time_to_next_viable_direction` (median trigger → first admitted candidate), `false_novelty` (n ≥ 5 generated), `agent_divergence` plus its **same-mode control**, `privacy_leakage`, `cost_of_novelty` (a zero denominator is `insufficient_data`, **not** `0`) and `personality_stability` (stored envelopes and mode assignments re-verified; expected 0). Each carries its window, its `n`, its source collections and its documented minimum, and reports `insufficient_data` below that minimum rather than a fabricated rate. Privacy leakage is measured, not asserted: the shared-scope artefacts are read back and checked against the private keys the baton allow-list forbids AND against markers lifted verbatim from this identity's own private stores (rejected hypotheses, changed premises, trace statements), and the count is reported with how many artefacts and markers were checked.
- **Experiment records + the ONE gated write** — `registerExperiment` records the brief's §7.4 shape as DATA (an arm is a label plus a config; checkpoints are names) and `compareExperiment` returns per-metric baseline vs treatment means, the delta, the direction, the target it applied (the brief's **"≥30% better useful novelty"**, named and overridable) and a verdict of `improved` / `not_improved` / `insufficient_data` **with the n of each arm and the threshold used**. The single write is `recordExperimentObservation`: `FOCUSED_IMAGINATION` on, trusted caller only, caller-owned (`user_id` is the caller's own — there is no parameter that could point it elsewhere), closed shape (an unknown key is refused by name) and idempotent per `{experiment, arm, metric, checkpoint}` (same key with the same numbers writes nothing at all and says so). It is the only path that reaches `registerExperiment`; every other view is read-only, with unit tests that pin the whole GET surface to leave the store byte-identical.
- **Two new MCP tools behind `FOCUSED_IMAGINATION`** — `get_imagination_metrics` (read, caller-pinned) and `record_experiment_observation` (the gated write), documented in `docs/MCP-TOOLS.md` (catalogue + the flag table: +10 → **91**, **92** with `CREATIVE_BATON_PROMOTION`, and **137** with everything on) and `.env.example` (including `IMAGINATION_METRICS_WINDOW_DAYS`, default 14). `docs/IMAGINATION-ROLLOUT.md` carries the staged rollout (per-identity personality → focused imagination → baton promotion → cognitive team), the metric gates each stage must pass, the kill switches (`PER_IDENTITY_PERSONALITY`, `FOCUSED_IMAGINATION`, `CREATIVE_BATON_PROMOTION`, `COGNITIVE_TEAM_ALLOCATION`, `COGNITIVE_ACTIVATION_KILL_SWITCH`), the executable rollback commands and the ITER-2 deployment precondition (server and bridge deploy together; the bridge sends its key) — and the dashboard's Rollout view derives every flag and kill-switch state from the environment rather than from constants.
- **Cognitive team — expiring modes, bounded inheritance, portfolio allocation, an independent first pass and synthesis (ITER-8, `COGNITIVE_TEAM_ALLOCATION`, default off)** — Phase 6 turns one identity into a **team** of cognitive roles without letting any of them read a peer's ideas or a parent's private memory. New `server/src/services/processing/cognitive-mode-service.ts`, `inheritance-envelope.ts`, `inheritance-policy.ts`, `inheritance-invariants.ts`, `cognitive-allocation-service.ts`, `independent-first-pass.ts`, `cognitive-team-collections.ts` and `cognitive-team-tools.ts`, plus `inheritance-envelope.schema.json` registered in the mission-cognition registry. Nothing in this iteration writes a shared scope: `thinking_mode_assignments`, `inheritance_envelopes` and `cognitive_portfolios` are **personal kinds**, so no row of theirs can carry a `shared_id` — and a synthesis carries `promoted: false`.
- **Modes expire, and the catalogue is the brief verbatim** — the eight Appendix C modes (philosopher, technician, strategist, creative, analyst, critic, verifier, synthesizer) are recorded with their **attention bias and obligation exactly as the brief states them**, each declaring which approved dimensions it may bias (`k` within ±25% of the parent's own value, `vector_fetch_limit` 1..20, `cap_pct` tightened within bounds) and never a hard invariant — the approved vocabulary does not CONTAIN one, so that is a property of the vocabulary rather than a rule to remember. An assignment carries a **required reason**, a start, an explicit `expires_at`, the policy version, the inheritance policy, the parent's disposition snapshot version and a reset behaviour; **expiry is computed at READ** (no cron, no sweep, no timer) and the transition is recorded **once** behind a guarded update; `renew` is the only path that moves the window (with a reason, extending from `max(now, current expiry)`), an expired assignment cannot be renewed at all, and the assignment's grant is hashed so a tampered mode/reason/actor/TTL is refused by name. A mode reaches the ITER-6 engine through the two knobs it already honours (the plan spread and the operator-family budget) — the engine is not reimplemented.
- **Inheritance is bounded, and the parent's configuration is never touched** — `createInheritanceEnvelope` builds an IMMUTABLE REFERENCE from an allow-list: `parent_identity_id`, a disposition snapshot (profile, version and a hash over an allow-listed subset of the parent's resolved configuration), the immutable bounds (message priority **10.0**, the working-memory/vector floors, the per-source cap bounds, the privacy policy), the approved dimensions, the parent's baseline and an expiry. `applyBoundedMutation` clamps an approved dimension into its documented range and records the clamp in the envelope's history; everything else is refused **by name**: `immutable_invariant` (the priority and every alias of it, the floors, the cap bounds, the privacy policy), `dimension_not_approved` (an unknown dimension, or one this envelope's MODE may not bias) and `out_of_bounds` (not a finite number, or an attempt to WIDEN a per-source cap above the parent's own bound). A mutation produces a NEW derived envelope (the parent's row is never rewritten, a derived scope expires with its parent, and the derived id is a function of the mutation chain). `verifyEnvelope` runs the Creative Baton's discipline — version, a CLOSED registered schema, the recomputed `policy_hash` — plus the invariants re-checked on the DECODED values, so a tamperer who recomputed the hash is still refused for the cap it widened, the k band it stretched or the fetch ceiling it raised. The parent's own configuration is byte-identical afterwards (this family has no write path to `system_settings` at all), and a taint suite plants markers in journals, reflections, episodic events, traces, seeds, lineages, beliefs and procedures and proves none reaches an envelope, its hash input or any tool output.
- **Allocation builds a portfolio, not one winner** — `allocatePortfolio` implements the brief's §4.5 score (`0.35*emotional_proximity + 0.25*task_skill_fit + 0.20*missing_approach_coverage + 0.10*recent_success + 0.10*availability - convergence_penalty - load_penalty`) with EVERY term and input reported in `allocation_report`. `missing_approach_coverage` is read from the archive's own coverage gaps (so the portfolio targets the bins nothing occupies), `recent_success` from the identity's recorded candidate outcomes and `availability` from its live mode assignments; the convergence penalty punishes sharing a mode with peers AND picking a further agent of a mode the portfolio already holds, and the load penalty punishes an identity that has just been cycling inside the persisted window. Selection is a documented deterministic greedy pass (coverage → the reserved evaluator → fill, identity-order tie-breaks), and one **verifier/critic that is not among the generators** is reserved with the reason `independent evaluator` (when the team holds none, the portfolio says so by name instead of inventing one).
- **An independent first pass that carries no peer content, and a synthesis that cannot launder it** — `planFirstPass` gives each agent its OWN generation request: the mission digest (ids, version, title, intent, the trace's problem-state digest, a summary of signal SHAPES, the coverage gaps and the exclusions as `{ref, kind, reason, text_hash}` FINGERPRINTS), its own envelope and mode definition, and the engine settings derived from them — no peer seeds, identities, envelopes or private memory; a request whose agent has no trace, or whose envelope is missing, expired, tampered with or granted for another mode, comes back `blocked` with the named reason and makes zero model calls. `runFirstPass` executes each ready request through ITER-6's engine, which reads that agent's OWN trace and archive (both `{user_id, mission_id}`-keyed, so the isolation is structural), and each agent's stream is derived from the pass, its MODE and its envelope scoring — never from a peer and never from the identity's private state, so a same-mode team converges (measured: identical portfolios) while a mixed-mode team spans the space. `synthesizePortfolios` keeps per-candidate provenance (a statement several agents produced keeps EVERY source — the merge collapses the statement, never the lineage), carries the exclusions verbatim, REFUSES an attempt to drop (`exclusion_dropped`) or rewrite (`exclusion_rewritten`) one, appends a `synthesis` lineage record and **cannot promote**.
- **Six new MCP tools** (`COGNITIVE_TEAM_ALLOCATION=1`, its own family flag) — `assign_thinking_mode` (the brief's named tool, with `renew`/`expire` folded in as explicit actions so every transition still needs a reason), `get_active_mode`, `create_inheritance_envelope` (with the bounded-mutation surface folded in), `allocate_cognitive_portfolio`, `plan_independent_first_pass` and `synthesize_portfolios`. Documented in `docs/MCP-TOOLS.md` (catalogue + the flag table: +6 → **87**, and **135** with everything on) and `.env.example`. With the flag off the tools are `Unknown tool`, nothing is written and no model call is made; every tool is caller-pinned and an untrusted caller cannot act for, or read, another identity.
- **Creative Baton, plateau cycles, controller adapter and resume (ITER-7, `FOCUSED_IMAGINATION` + `CREATIVE_BATON_PROMOTION`, both default off)** — Phase 5 closes the loop: a **stalled** mission runs **exactly one** imagination cycle, receives a **sanitised, versioned Creative Baton**, has its candidates turned into controller work items, records what happened, and resumes correctly after a restart. New `server/src/services/processing/imagination-cycle-service.ts` (plateau evaluation + the cycle orchestrator), `creative-baton-compiler.ts`, `creative-baton-promotion.ts`, `imagination-outcome-service.ts` (adapter + outcome feedback), `creative-baton-collections.ts`, `imagination-cycle-config.ts` and `creative-baton-tools.ts`, plus `creative-baton.schema.json` registered in the mission-cognition registry. **The gates, in the contract's fixed order:** single-flight (a concurrent caller joins the running cycle instead of starting a second one) → the **persisted** cooldown → the per-mission **window budget** (cycles *and* measured tokens from the usage ledger) → the **plateau evaluation**. `force: true` bypasses the plateau gate only — never the cooldown or the budget — and a **skipped cycle writes nothing at all**: no cycle row, no state change, no baton, no model call. **Nothing about the cooldown, the budget or the claim lives in memory:** `imagination_cycle_states` holds one row per `{user_id, mission_id}` (cooldown deadline, window counters, last cycle/baton/stop reason, the no-new-cells streak, the novelty means), and `imagination_cycles` holds one row per claimed cycle, unique per **`{user_id, mission_id, cycle_id}`** with a **derived** `cycle_id` (`imagination_cycle_<scope16hex>_v<version>_c<ordinal>`, where the scope digest covers the identity AND the mission), so two concurrent callers of ONE mission compute the same id and exactly one insert wins, while two DIFFERENT missions that share (version, ordinal) derive different ids and each run their own cycle — the claim lookup is scoped to the same key, so no mission can read, replay or inherit another's trace, baton or counts. A completed row replays and an abandoned one is stepped over rather than wedged. The plateau is the brief's §4.1: **below-minimum active candidates** (`IMAGINATION_PLATEAU_MIN_CANDIDATES`, 3), **novelty gain below ε over N rounds** (`…_NOVELTY_EPSILON` 0.05 / `…_NOVELTY_ROUNDS` 2, derived from the persisted means), a **repeated failure signature**, **archive coverage below a floor** (6 cells) and **contradiction pressure above a threshold** (2 live contradictions) — each reported with the evidence that decided it, so "not a plateau" comes with five numbers rather than silence. Every cycle records the counts, the effective budget and what was actually spent, the coverage view **with its scan bounds and a `truncated` flag**, and which **stop condition** fired (budget exhausted · coverage target reached · no candidate above the novelty/coherence floor · two consecutive rounds without a new cell · a high-value candidate promoted and the inventory restored · privacy validation failed · mission cancelled/superseded · completed), with all of them reported and the first met one in precedence order winning
- **The Creative Baton is an allow-list, and promotion is explicit and idempotent** — `compileCreativeBaton` builds the brief's §4.3 packet **field by field**: the portfolio carries the candidate's own hypothesis, mechanism, descriptor bins, scores, cheapest test, lineage ref and `privacy_safe: true` (and nothing else), `attention_targets` is DERIVED from each signal's kind and calibration numbers (never its statement or its own `why_operationally_relevant`), and `excluded_regions[].pattern` is a FINGERPRINT (`region_N:<kind>:sha256:<16 hex>` — never the ruled-out text). Evidence refs, changed premises, bridge paths, parent links and cell keys have no place in the shape at all. Every compiled baton is validated against `creative-baton.schema.json` and **secret-scanned with the same patterns the mission's own batons use** (`assertNoSecretMaterial`) before it is written, and carries a `payload_hash` over the canonical sanitised payload. `promoteCreativeBaton` is the ONLY code that writes a shared scope: it requires **both** flags and a **trusted** caller, **re-validates the stored document** (schema, secret scan, `creative_baton_version`, and the payload hash recomputed against the one the compiler wrote), refuses a tampered baton with a **named reason** (`payload_hash_mismatch`, `schema_invalid`, `secret_material`, …) instead of sharing it, writes the promotion audit row (`creative_baton_promotions`: promoting identity, timestamp, schema version, payload hash) and is **idempotent** — promoting the same payload twice reports the existing promotion and writes nothing
- **Controller adapter + outcome feedback** — `batonCandidatesToWorkItems` turns a baton's eligible candidates into work items **through the existing funnel**: `work-item-generator.ts` gained an `extra` input and `SchedulerService.upsertWorkItems(missionId, { extra })` forwards it, so there is no new write path into `cognitive_work_items`, the items get the mission's own priority feature vector, the funnel's `{mission_id, trigger, description}` dedupe makes the adapter idempotent, and each item carries `[creative_baton <id> seed <id>]` in its description plus a `provenance` row field (`{source, baton_id, seed_id, cycle_id, requested_by}`). The trigger **reuses the existing `manual` value** (no enum member had to be invented: the item exists because a caller explicitly asked for it) with mode `explore`; an untrusted caller may only adapt a **promoted** baton, because the work queue is shared state. `recordCandidateOutcome` (`useful_information` / `mere_variance` / `unnecessary_cost`) feeds the archive's identity-bound `recordOutcome`, the existing `trigger-telemetry` instrument (measured token cost, grouped under the new `imagination_candidate` trigger type; the telemetry note carries ids only, never the caller's `detail`) and a **capped** novelty-drive replenishment (`+0.05` per useful outcome, at most `0.2` per identity and mission per rolling 24 h, computed from the **stored** outcome rows so a restart cannot refill the same budget). Idempotent per `{seed, outcome}`: a repeat is recorded once and reported as a repeat; a different outcome for the same seed is a new record
- **Five new MCP tools** (`FOCUSED_IMAGINATION=1`, plus `promote_creative_baton` behind `CREATIVE_BATON_PROMOTION=1` too) — `run_imagination_cycle` (run, or `mode: "evaluate_only"` / `dry_run` to see the plateau conditions, the persisted state, the window budget and the cooldown with **zero writes**), `get_creative_baton` (caller/scope-aware: own batons plus promoted ones), `promote_creative_baton` (trusted callers only), `baton_candidates_to_work_items` and `record_candidate_outcome`. Documented in `docs/MCP-TOOLS.md` (catalogue, the flag table: +8 → **89**, and **90** with `CREATIVE_BATON_PROMOTION=1`; the promotion flag on its own adds nothing) and `.env.example` (both flags + the cycle budget/cooldown knobs). With either flag off the tools are `Unknown tool`, nothing is written and no model call is made
- **`imagination_cycle_states`, `imagination_cycles` and `idea_candidate_outcomes` are personal kinds** — added to `PERSONAL_KINDS`, written through `resolveWriteScope`/`stripSharedId`, so the cooldown/budget state, the cycle ledger and the outcome rows can never carry a shared scope. `creative_batons` is deliberately NOT a personal kind (the compiled baton is the one shareable artifact, written privately at compile time and promoted by the gated promoter) and `creative_baton_promotions` is the team-scoped audit of that promotion. Indexes are owned by the feature (`ensureCreativeBatonIndexes`, the lazy house guard memoised per store) and deliberately NOT declared in `MEMORY_SYSTEM_INDEXES`
- **ITER-6 residuals fixed** — (F1) **one effective threshold**: `CONTAINMENT_THRESHOLD` now IS `PARAPHRASE_THRESHOLD` (0.72), so the containment branch fires exactly at the gate the archive compares against and the 0.7-vs-0.72 dead band is gone; (F2) the **seed path compares like the exclusion path** — hypothesis against hypothesis, mechanism against mechanism and concatenation against concatenation, taking the maximum — so a verbatim hypothesis with a freshly worded mechanism can no longer dilute the overlap and be admitted as new; (F3) the **finite vacuity stoplist and the absence of synonym rewriting are documented in the module header** (behaviour unchanged). Coverage now reports its **scan bounds** (`cells_limit`/`cells_scanned`/`cells_truncated`, `seeds_dedupe_limit`/`seeds_scanned`/`seeds_truncated`) and a single `truncated` flag, in the coverage view **and** in the baton, so a bounded scan is never presented as the whole archive
- **Imagination engine + quality-diversity idea archive (ITER-6, `FOCUSED_IMAGINATION`, default off)** — Phase 4 turns a Salience Trace into a **diverse, reproducible portfolio of testable hypothesis seeds**. The brief's **ten operator families** (`assumption_inversion`, `representation_shift`, `distant_analogy`, `constraint_mutation`, `boundary_extreme`, `causal_reversal`, `contradiction_preservation`, `tool_invention`, `random_semantic_bridge`, `counterfactual_world`) are selected **from the trace itself** — tensions and persistent pulls drive constraint mutation and contradiction preservation, absences invert assumptions, surprises reverse causes, attractions shift representation, questions bridge distant associations — with intensity setting the score order and a **seeded** tie-break deciding the rest, so the run's `operator_plan` records which operators ran, on which signal ids, and why (an operator that cannot run, e.g. no bridge path, is recorded as *skipped*, never run as a fabrication). New `server/src/services/processing/imagination-service.ts` (+ `imagination-operators.ts`, `imagination-collections.ts`, `imagination-tools.ts`) and `idea-archive-service.ts`. **Determinism is structural, not hoped for:** every random choice comes from a seeded PRNG (mulberry32 over a hash of the run's seed) and every id is **derived** (`sha256` over the seed's content + the seed + the mission) — never a random UUID — so two runs with the same seed over the same inputs produce a byte-identical portfolio (`portfolio_digest`, computed over the payload with timing/bookkeeping fields stripped, proved across an advanced clock by test), and a different seed yields a different, still schema-valid portfolio. Every seed must cite the trace signal ids or the mission's ledger/delta/work-item/baton ids: an unresolvable ref is **dropped and counted**, never stored and never replaced by an invented one, and a seed left with no evidence is dropped with a counted reason; **novelty is measured against the archive** (`min(model claim, 1 − max similarity)`), not taken on faith
- **The distant-association walk returns the path** — a bounded (2–3 hops, ≤3 paths, ≤400 nodes / ≤1200 edges), **seeded**, **cycle-safe** multi-hop walk over the caller's own `knowledge_nodes`/`knowledge_relationships` with a low-degree preference, so `random_semantic_bridge` and `distant_analogy` must **state the bridge** the walk found (a bridge seed without a path or without a stated bridge is dropped and counted). Deviation from the brief, recorded: the walk uses this repo's real edge collection (`knowledge_relationships`), not the `knowledge_edges` name the contract assumed
- **Quality-diversity archive** (`idea_archive_cells`, one cell per descriptor-bin tuple) — five descriptor dimensions (`mechanism`, `representation`, `violated_assumption`, `evidence_family`, `test_strategy`), a documented quality function (`quality = f(novelty, coherence, testability, information_gain)`, fixed weights summing to 1), and one **incumbent per cell** (the highest-quality seed; a challenger that does not beat it is admitted below the incumbent and the cell's history says so). **Deterministic dedupe with recorded reasons:** exact duplicates are `duplicate_of`, near-duplicates `paraphrase_of` and matches against the mission's exclusion list (rejected ledger hypotheses + the trace's own low-confidence regions) are `excluded_region`, decided by **content-token containment** (`|A ∩ B| / min(|A|, |B|)` over stopword-filtered tokens, at least two shared tokens, at `CONTAINMENT_THRESHOLD` — which since ITER-7 **is** `PARAPHRASE_THRESHOLD`, see the residuals entry above; it was 0.7 while the gate was 0.72, the dead band that entry closes) *as well as* by Jaccard over the normalised token sets (`PARAPHRASE_THRESHOLD = 0.72`, with the length guard `LENGTH_GUARD_RATIO = 0.5` applied only where containment is genuinely low) — so a stored statement padded with hundreds of extra characters is still a restatement rather than a new idea. Rejections are **stored with their reason**, which is what makes an exclusion durable — and what a **changed-premise re-entry** must cite: a ruled-out idea comes back only with a **valid** premise (a complete sentence that is *not* a no-change assertion — `nothing has changed`, `no change`, `unchanged`, `as before`, … — and that introduces at least two content tokens the excluded text does not already contain) **and** a lineage link to the prior rejection, and the cell's history records the re-entry. Coverage is the sanitized surface (`cells_total`, `cells_by_dimension`, `new_cells_this_cycle`, `occupancy`, `gaps` and incumbent ids/bins/quality) and carries **no seed statement, mechanism or evidence text**
- **`generate_imagination_seeds` + `get_idea_archive` MCP tools** (`FOCUSED_IMAGINATION=1`, default off) — the run tool is a **write** an untrusted caller may only use on a mission it owns and it **does not promote anything** (no promotion path exists before Phase 5); the read tool is caller-pinned and returns the sanitized coverage view plus incumbent summaries (cell key, bins, quality, seed ids). Documented in `docs/MCP-TOOLS.md` (catalogue + the flag table: +4 → **85**, 86 with the personality flag, 110 with the cognitive-control row, 123 with a scheduler mode, 124 with all of them on), the README and `.env.example`

- **Six ITER-8 refinements, found by an independent verifier (cognitive team)** — each correction is pinned by a test written to FAIL against the sources as they stood (the new `cognitive team — the refinement fixes` suite, 8 tests). **(1) The duplicate-pick convergence penalty was inert at selection time:** `best()` compared `staticScore − 0.2 * row.duplicatePicks`, but `duplicatePicks` was only written inside `select()` AFTER a row had won, so it was always 0 during comparison and the penalty could never change who was picked — two otherwise-equal same-mode candidates tied on identity order and the second one was seated. The cost is now computed from the LIVE selection at every comparison (`duplicatePicksIn`), so a second agent of a mode the portfolio already holds loses to a different-mode candidate by exactly `CONVERGENCE_PENALTY_PER_DUPLICATE_PICK`; `select()` still records what the pick actually paid. **(2) A read could shorten a LIVE mode:** `activeMode`'s read-computed expiry matched `{assignment_id, status:'active'}` without pinning `expires_at`, so an interleaved renewal (issued while the mode was still live, its write landing after the read's snapshot) was reverted by the stale read's `status: 'expired'` write — the renewal was on record but the mode read as dead forever. The guard now pins the exact `expires_at` the read computed from, and a guard that loses RE-READS the row and returns the state actually stored instead of writing the stale conclusion (a later read still records the expiry once the renewed window really has passed). **(3) Portfolio idempotency depended on candidate list order:** `portfolio_id` was derived from the candidate list in the order the caller sent it, so a shuffled list of the SAME candidates missed the stored row and wrote a second, identical portfolio. The service now caps a reason at `MAX_REASON_LENGTH` (500, the schema's own bound — refused, never truncated, on assign, renew AND expire) and requires a TTL to be a real integer number inside the documented window (no coercion). **(5) A mode could be assigned on a terminal mission:** `assignMode` never consulted mission status, so a mode granted on a `cancelled`/`completed` mission read back active. A `running` claim whose `created_at` is missing or unparseable could never satisfy the staleness test, pinning `{user, mission, cycle}` at `in_progress` forever (unstuck only by inventing a new cycleId); an un-ageable claim is now reclaimed as failed, while an ageable one still waits for the timeout + grace window. Also: `sanitizeTrigger` no longer stores a dangling separator (`'Manual Trigger!'` → `'manual_trigger'`); wrong-typed tool arguments are reported as a readable `❌ Invalid arguments for <tool> — <field>: <message>` (the mission-cognition handler style) instead of escaping as a raw ZodError to the outer catch; and `clamped_values` is documented precisely and split, so `coerced_values` isolates numeric strings coerced with `Number()` from genuine range clamps
- **Beliefs leaked between identities and evaporated on restart** — `trackBelief` hardcoded `user_id: 'default'` on insert while `getAgentBeliefs` filtered by `entity_name` alone, so every identity read (and overwrote) the same rows, and the whole procedural map died with the process. Beliefs are now written and read per identity (a write without an identity is refused, never attributed to anyone) and procedural patterns are persisted per identity, so an untrusted caller can no longer read or write another identity's beliefs or habits, and a restart no longer forgets them. `server/tests/unit/self-model-identity.test.ts` proves both, including the restart and the migration's second-run no-op; `tests/security/user-id-scoping.test.ts` covers the beliefs/procedures cases
- **Concurrent personality writes lost a version increment** — the flag-on `PUT` read the record and then wrote `version + 1` unconditionally, so two simultaneous updates both reported the same version and the second silently overwrote the first. The write is now a bounded compare-and-set on the observed version (`updateOne({key, version: observed})`, re-read and retry on a miss), so interleaved updates land as sequential increments with the last writer's payload; exhausted retries return **409** rather than a version that was never stored
- **Two identities creating their first personality record at once silently discarded a payload** — the create branch upserted on the key alone, so a record another writer created between our read and our write was matched and overwritten with `version: 1`, losing that writer's payload and its increments. The create is now guarded with `{ key, version: { $exists: false } }` and a create that *matches instead of inserting* (or that the unique `key` index refuses as a duplicate) is retried through the guarded update path: `version` is the number of successful writes, and every landed write moves it by exactly one
- **A hand-written or pre-versioned identity record was permanently unwritable** — the write guard asked for the *absence* of `version` whenever the stored value was not a finite number, which a record that has the field never satisfies: every attempt missed and the write returned **409** forever. The guard now pins the observed raw value (equality on whatever is stored, including `null` and a string), and `resolve()` keeps reporting `version: 0` for a non-finite or absent version, so a repaired write lands as version 1
- **A retried personality write recorded a stale `updated_at`** — the timestamp was captured before the retry loop, so a write that lost a race and landed on a later attempt claimed the time the request started. It is now stamped inside the loop, per attempt
- **Dashboard Personality tab interpolated server values into `innerHTML()` unescaped** — `resolved_for` (and the origin label built from it), the identity selector's ids, profile names and the weight grid are HTML-escaped through a shared `escHtml()` helper, closing a self-XSS in `renderPersonalityResolution()`
- `vector_search` scored a frozen candidate slice — `find(...).limit(50)` with no sort meant every query re-ranked the same documents (measured: a four-day window of mid-July, 0 of 50 newer than seven days, out of 45k embedded facts in scope). Candidates are now the newest-in-scope ∪ query-matched documents; undated documents no longer score `NaN`
- Long documents were truncated at the model's 512 positions and mean-pooled once, so everything past the first window was invisible to search. Embedding now splits into overlapping windows (1,000 chars, measured ≤350 tokens) and averages their vectors; `server/scripts/reembed-long-docs.mjs` refreshes documents embedded before the change
- `ensure-bridge.sh` step-3 rewrite condition now also compares `mcp_url` against `KATRA_HOST` (a non-login run could pin `localhost` permanently)
- Cross-identity semantic leak in `search_memories` — vector pass scoped to the caller's view
- Hybrid scope regression in `search_memories` keyword pass — `$or` nested under `$and`
- Agent-message pickup missed newly provisioned identity attention names; OR-aware search + vector fallback
- Wake scripts now handle missing `KATRA_HOST`, legacy keys, and whitespace-padded config values
